# 课途规划器新页面设计

## 意图

在 `fudan-course-atlas` 网站中增加独立的 `/compass` 选课规划页面，复用现有课途规划器的对话式引导、课程证据与排课逻辑。用户登录后可以在账号中保存规划状态；使用 AI 规划前需要输入自己的 DeepSeek API Key。Key 只在当前浏览器会话中保留，刷新或退出后重新输入。

## 目标与边界

- 新页面从课程地图网站进入；不替换首页或现有课程检索、课评、积分等功能。
- 未登录访客仍可浏览页面与课程知识；AI 规划和个人资料云端同步要求登录。
- 大模型负责询问目标、时间预算、已修课程和偏好，并解释课程证据；现有确定性工具负责候选课表、学分和时间冲突检查。
- 用户自行提供 DeepSeek API Key；后端只为模型请求转发 Key，不保存到账号数据、数据库、浏览器持久存储或日志。
- 本次不改动独立站点 `fudan-course-compass.xiasinm.chatgpt.site` 的部署或本地数据。

## 已知项目现状

- 目标 GitHub 项目为 `pythonbug225/fudan-course-atlas`，当前工作副本是 `D:\codex\fudan-course-atlas-work`。主课程地图由静态 `public/index.html` 运行，项目使用 Next/Vinext、Cloudflare Worker 与 D1。
- 项目已有站点原生 ChatGPT 身份工具 `app/chatgpt-auth.ts`、登录/登出路径和 `/api/session`；已有 API 通过可信的 `oai-authenticated-user-id` 请求头区分账号。
- 项目已有 D1 `DB` 绑定、社区投稿与积分的数据表及 API 模式，可沿用身份校验和数据库迁移流程。
- 独立版课途通过公开页面资源提供 HTML、CSS、JavaScript 模块及课程数据；其 `app.js` 将 `course-compass-v2` 状态保存在该域名的 `localStorage`，Key 只放在页面内存中，并向 `/api/model` 转发。Atlas 仓库目前没有课途页面、规划逻辑或这个模型代理接口。
- 浏览器按来源隔离 `localStorage`。Atlas 新页面不能直接读取独立课途域名中已有的本地记录。旧站仍保持可用；本设计的首次本地/云端选择仅针对 Atlas 新页面中产生的数据，不承诺自动迁移旧域名中的浏览器状态。旧版完整记录迁移可作为单独的导入/导出功能处理。

## 考虑过的做法

1. **复用现有课途 HTML/JavaScript 模块并接入 Atlas 登录与 D1（选定）**：在 `/compass` 提供课途界面，保持原有引导与排课逻辑，增加账号保存和模型代理。可较少改写算法，功能风险较低。
2. 用 React/Next/Vinext 重写整个规划器：可以完全融入现有组件体系，但需要重写多轮规划、课程详情、方案比较和课表界面，工作量及回归风险更高。
3. 在 Atlas 页面中 iframe 嵌入独立课途：开发量较低，但它仍在另一站点，无法统一登录和个人数据存储，不满足此次目标。

用户选择做法 1，并选择站点原生登录（接受可能需要 ChatGPT 账号）；用户还指定本地和云端两份数据都要保留，首次冲突时由用户选择。

## 页面与服务设计

### 页面集成

- 新页面路径为 `https://fudan-course-atlas.xiasinm.chatgpt.site/compass`。
- 把课途界面与其规划模块放入 Atlas 的静态资源目录，以同源地址加载课程数据和 API；在现有课程地图导航中增加“课途规划”入口。
- 保留课途当前的目标选择、学习预算、培养方案、对话、候选课表、课程证据、审计和方案比较流程；不自动代替用户选课。
- 使用课途原有课程数据结构，避免在未核对字段来源与含义前将 Atlas 课程数据直接替换进去。静态课程数据按需加载，不在首页初始化时下载。

### 登录与个人数据

- 使用 Atlas 已有的站点原生登录流程，不新增密码、邮箱验证码或学校 CAS。
- 对话规划和个人资料云端读写都必须登录；课程浏览和公开检索保持开放。
- 服务端只从可信身份头解析用户 ID；所有数据库查询按该 ID 限定，忽略客户端提交的 user ID。
- 通过 D1 保存用户自己的规划快照，覆盖课途现有 `persist()` 中的个人字段：培养方案、学期、目标、学分上限、学习预算、已修课程、约束、A/B 方案、记录、认定、审计检查、分配状态与方案配置。不保存聊天记录和 API Key。
- 初次同步时，只有本地数据就保留本地副本并上传；只有云端数据就加载云端；两边都有时，分别保留两个快照并展示选择器，用户选择用于当前账号的快照。替换当前云端快照前保留旧版本，不静默覆盖；跨设备并发修改用版本号拒绝静默丢弃较新数据。
- 退出时清空页面内的 Key、对话和身份显示状态；本地规划缓存仍保留，供下一次登录时选择。

### AI 与 API Key

- 复用课途现有的多轮模型规划和工具调用，保留“模型解释、规则引擎校验”的分工。
- 在 Atlas 中新增登录保护的模型转发 API；仅允许 DeepSeek 固定服务地址，限制请求体大小并校验输入。Key 通过请求头短暂传给服务端，只用于转发，不记录请求头或请求正文中的 Key。
- 连接测试失败、模型请求报错、用户清除连接或退出时，将页面内存中的 Key 清空并提示重新输入。
- 模型只能基于页面提供的课程与班次证据提出建议；未找到证据时明确说明，不把模型文本当成课程数据库事实。

## 非目标

- 不修改独立版课途的线上站点，也不尝试跨域读取它的 `localStorage`。
- 不持久化 DeepSeek API Key，不引入其他模型供应商。
- 不新增学校认证、邮箱密码账号、用户之间的计划共享、自动选课或教务系统提交。
- 不重写课程知识库或 Atlas 的排课/课程计算能力。

## 验收标准

- Atlas 首页保留原功能，并出现通往 `/compass` 的入口；直接打开 `/compass` 能加载规划器。
- 未登录用户能浏览课程；发起 AI 规划或云端保存时进入站点原生登录，登录后返回 `/compass`。
- 个人数据 API 按登录身份隔离，用户无法读取或覆盖他人的快照。
- 首次同步遇到本地和云端两份数据时，两份都保留且用户能选择；并发版本冲突不会静默覆盖。
- API Key 不写入持久化存储或日志；刷新、退出、清除连接或请求失败后必须重新输入。
- AI 规划仍能通过已有确定性规则检查候选组合，并展示对应课程证据；公开课程浏览不依赖登录或 API Key。

## 发布前置条件

- 当前 `.openai/hosting.json` 只有 D1/R2 绑定，没有 Site `project_id`；正式部署前需确认 Atlas 站点的托管项目身份与可用发布路径。
- 新页面应与现有工程资料 PR 分开审阅，避免把独立功能混入课程资料变更；发布目标由仓库现有部署流程确认。
