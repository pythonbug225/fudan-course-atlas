# 复旦选课地图积分账本设计

## 意图

把当前只存在浏览器 `localStorage` 中的签到和试卷单文件积分演示，改为由本站服务端维护的账户积分账本。用户登录后可在不同设备查看同一余额；每日签到增加 5 分；第一次通过本站打开一份已匹配的试卷文件扣 1 分，同一用户再次打开同一文件不重复扣分。

## 当前情况

- 线上页面目前仍展示旧导航；积分/试卷前端只在工科 PR 分支中，尚未部署。
- PR 分支的积分余额为演示值 120，签到和文件解锁记录都写在浏览器本地。
- 仓库已有 ChatGPT 登录身份读取、课评投稿 API，以及 `.openai/hosting.json` 中的 D1 `DB` 和 R2 `BUCKET` 绑定；积分 API 和积分表尚不存在。
- 试卷索引中的文件链接指向公开 GitHub 仓库，因此任何人都可以绕开本站直接打开文件。
- 现有社区投稿会直接公开保存，没有待审状态或管理员审核界面；页面上的课评/资料奖励目前只是拟议规则。

## 目标

- 以服务端提供的 `oai-authenticated-user-id` 区分用户，不在浏览器存余额。
- 由 D1 保存不可变积分事件，并通过唯一事件键保证重复请求不重复签到或收费。
- 以服务端日历 `Asia/Shanghai` 判断签到日期，每个用户每天至多 +5 分。
- 每个有效试卷文件 ID 首次本站解锁扣 1 分；重复解锁免费；余额不足、无效 ID 或无匹配链接时不打开文件、不扣分。
- 由服务端校验文件 ID 和固定 GitHub 链接白名单，费用始终由服务端定为 1 分，不接受客户端传入金额或 URL。
- 前端展示真实余额、签到状态、近期账目、登录引导、余额不足和服务失败状态；移除演示余额、示例流水和本地积分存储。
- 课评及资料浏览继续免费。

## 非目标与限制

- 保持 `fudan-exam-paper` 公开开源。积分只能约束本站提供的解锁入口及本站账目，不能阻止访问者从公开 GitHub 直接打开同一文件。界面必须明确说明此限制；不把本站积分宣传成访问控制或付费墙。
- 本次不迁移试卷文件、不调整 GitHub 仓库可见性，也不复制试卷到 R2。
- 本次不发放课评或资料投稿奖励。页面可以保留 +20/+10 作为待审核规则草案，但必须标明尚未接通。后续要发奖励，需先有投稿待审状态和受限审核流程。
- 不新增独立 OAuth、支付、现金兑换、积分转让或浏览器侧身份模拟。
- 不导入 `localStorage` 中的演示分数；真实账户初始余额为 0。

## 方案比较

1. **D1 账户账本，公开文件继续直链（选用）**：以现有 ChatGPT 登录身份和 D1 记录积分；前端通过 API 签到与申请逐文件解锁。保留仓库开源和当前 GitHub 文件入口，缺点是公开原链接可绕过本站账目。该方案符合用户此前保持试卷开源的决定。
2. **真正限制访问**：把文件放入私有 R2，并停止公开原始 GitHub 文件入口，再由验证身份并扣分的 Worker 按单文件返回内容。只有同时撤掉公开副本/入口才能有效，改变现有开源方式及文件托管，超出本次方案。
3. **继续使用浏览器本地存储**：改动小，但换设备、清理浏览器数据和篡改本地数据都会破坏余额；不满足真实积分账本需求。

## 设计

### 数据模型

在 D1 中增加追加式 `point_events` 表，记录事件 ID、用户 ID、事件类型、唯一事件键、积分变动和创建时间。对 `(user_id, event_key)` 建唯一约束，并建立按用户和创建时间读取流水的索引。签到键为 `checkin:<上海日期>`；试卷键为 `exam:<文件ID>`。余额由用户所有事件的 `delta` 求和，不把余额放在前端或由客户端决定。

新建 Drizzle schema/migration，保留现有 migration，不改写历史 SQL。提交前核对生成 SQL 与现有 D1 命名一致。

### API

- `GET /api/points`：未登录返回未登录状态；登录后返回账户余额、上海时区当天签到状态和最近账目。
- `POST /api/points/checkin`：要求登录和同源请求；幂等地写入当天 `+5` 事件，返回当前余额及是否已签到。
- `POST /api/exams/:fileId/unlock`：要求登录和同源请求；从服务端试卷索引校验 ID 与允许的公开 GitHub 单文件地址。通过一个原子、条件化的 D1 写入完成余额检查与扣分；并发重复请求只扣一次。已解锁时返回原地址但不再扣分。余额不足返回明确状态，不返回可打开链接。

所有 API 忽略客户端提交的积分数、用户 ID、日期和目标 URL。保留本站既有 `json` 响应和 `Origin` 检查习惯。错误响应不泄露其他用户的记录。

### 前端

- 积分页通过 `/api/points` 加载真实账户；未登录时引导顶层跳转到 ChatGPT 登录，返回积分页。
- 签到按钮请求服务端签到，页面在服务端确认后更新余额；重复签到展示已完成状态。
- 每个试卷文件按钮先请求单文件解锁。成功后呈现明确的“打开这一个 GitHub 文件”链接；不在异步请求后调用 `window.open`，避免浏览器拦截弹窗。
- 已解锁文件可再次免费打开；未匹配链接仍禁用且不调用扣分 API。
- 显示登录、加载、余额不足、已签到、重复解锁和网络错误状态；API 失败时不伪报成功，也不显示能够绕过积分直接打开的本站按钮。
- 将“公开 GitHub 文件可直接访问，不受本站积分限制”放在积分和试卷入口附近。
- 拟议的投稿奖励不出现在真实账目中；在审核能力接通前继续显示为未启用的规则草案。

### 安全与并发

- 以平台注入的身份头识别账户，未登录用户不可签到或扣分。
- 对写接口检查本站 `Origin`；金额、日期、用户身份、文件链接均由服务器确定。
- 唯一事件键处理重试与并发，条件化扣分保证余额不低于零。
- 文件 ID 必须存在于受控目录且 URL 必须符合固定 GitHub 仓库路径；无效文件不记账。
- D1 的真实积分仅表示本站操作历史。由于目标文件在公开仓库，不能据此判断用户没有直接访问文件。

## 验收条件

- 同一用户同一天多次签到最终只有一笔 `+5`。
- 不同用户拥有互相隔离的余额与账目。
- 同一用户对同一文件并发或重复解锁仅扣一次；不同文件分别扣 1 分。
- 余额不足、未登录、无效文件 ID、无匹配地址、写入失败时都不展示成功链接且不产生错误扣分。
- 页面不再展示 120 演示余额、示例活动数据或浏览器本地积分账本。
- 签到日按 `Asia/Shanghai` 计算；页面公开说明原始 GitHub 链接仍可绕过本站。
- 当前 PR 分支的前端和 API 改动经本地构建/手工流程核对；部署需确认站点项目和发布权限。

## 部署约束与风险

- 当前本地 checkout 处于 sparse-checkout；后端源文件在 Git 树中但未展开到工作区。实现前需仅展开必要的 `lib`、`db`、`drizzle` 与 `.openai` 文件，保留用户的 sparse-checkout 其余配置。
- 当前 Sites 工具没有列出该域名对应的项目，无法在本会话通过 Sites 管理器读取生产数据库或发布。代码可更新到已存在的工科 PR；线上可见仍取决于 PR 合并/站点发布流程。
- D1 迁移需由部署流程应用；本地和线上数据库状态不同。未确认线上迁移成功前，页面应将 API/数据库不可用显示为失败，不回退到本地伪积分。
- 发布前需确认登录身份头在目标站点 Worker API 中正常注入，并核实 D1 迁移应用状态。
